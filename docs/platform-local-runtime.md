# MedDecode local platform runtime

Run `npm run dev` at the integration repository root. The launcher starts the existing FastAPI application on 127.0.0.1:8000, Express on 127.0.0.1:3000, and Vite on 127.0.0.1:5174 (or 5175 if 5174 is occupied). It generates an ephemeral internal token unless `MEDDECODE_INTERNAL_TOKEN` is provided, passes it to backend and intelligence processes, and does not pass it to Vite. It does not start a worker by default. Press Ctrl+C in the launcher terminal; it stops the processes it started. On Windows the launcher currently uses `taskkill /T /F` to ensure process-tree cleanup; shutdown is therefore bounded but not graceful for in-flight OCR. Do not stop while an approved job is running without a separate operational decision.

Configure the existing `backend/.env` from `backend/.env.example`, keeping `PROCESSING_WORKER_ENABLED=false`. Configure the intelligence service in `intelligence/.env` from `intelligence/.env.example`, especially `MEDDECODE_EASYOCR_MODEL_DIRECTORY` and the existing restricted catalogue settings. For local catalogue access, provide `MEDDECODE_CATALOGUE_ENV`, `MEDDECODE_CATALOGUE_HOST`, `MEDDECODE_CATALOGUE_PORT`, `MEDDECODE_CATALOGUE_DATABASE`, `MEDDECODE_CATALOGUE_USER`, and `MEDDECODE_CATALOGUE_PASSFILE` (or an existing process `PGPASSFILE`). For a hosted reader, supply the existing dedicated read-only identity, passfile, CA and `MEDDECODE_CATALOGUE_SSLMODE=verify-full`. Python still connects directly to the catalogue through that existing provider because Layer 4 currently requires it; no application persistence privileges are needed. Do not place real secrets in example or tracked files.

The Python service offers `GET /health` (process liveness), `GET /ready` (EasyOCR initialization, token availability and catalogue configuration; it does not test catalogue connectivity), and `POST /api/v1/intelligence/process` (private bearer token, binary body and base64 Contract-v1 metadata in `X-MedDecode-Contract`). Node validates responses against Contract v1 before existing fenced persistence. The service runs one document at a time, bounds byte count and duration, validates file signatures and uses existing image/PDF decoding. A timed-out native OCR operation can continue in the service process; its concurrency gate remains held until it actually stops. It does not persist jobs or fetch arbitrary S3 references. Native OCR cancellation and graceful forced shutdown need additional work before production deployment.

Backend `/health` reports liveness. `/ready` reports Python readiness and a separately configured database probe; it returns 503 when `BACKEND_READINESS_DATABASE_URL` or `BACKEND_READINESS_DATABASE_CA_FILE` is missing. Use a separate restricted read-only login and verify-full CA. The check does not establish Supabase Auth availability, worker readiness, RLS behavior, or end-to-end processing. Never use a privileged administrator or service role for this probe. A development-only loopback database may explicitly use `BACKEND_READINESS_LOCAL_NO_TLS=true`.

The existing restricted Node worker is a separate process. Its actual processing path uses `PYTHON_INTELLIGENCE_URL` and `MEDDECODE_INTERNAL_TOKEN`; the subprocess client remains for legacy local tests. Optional launcher supervision is off by default. `MEDDECODE_START_CONTROLLED_WORKER=true` requires explicit scoped RPC mode, automatic authorization, `WORKER_SINGLE_ATTEMPT=true`, the dedicated automatic-worker login, one worker instance, separate `WORKER_AWS_ACCESS_KEY_ID`/`WORKER_AWS_SECRET_ACCESS_KEY`, and verified TLS. This opt-in can process hosted work and requires separate approval and fresh preflight; setting it alone is not authorization. The service token must match between Python and worker. A dedicated host secret manager or protected local session must supply secrets. Admission and frontend/backend upload flags are separate decisions.

For an independent fictional OCR test, configure the catalogue and model variables above and a private `MEDDECODE_INTERNAL_TOKEN` of at least 32 characters; start `intelligence\.venv\Scripts\python.exe -m uvicorn app.integration.http_service:app --host 127.0.0.1 --port 8000`. Use the same server-side token in a trusted local client; never put it in the browser. The automated HTTP format test `backend/tests/http-python-real-ocr.manual.ts` uses a dedicated test server on 127.0.0.1:18000 and requires `MEDDECODE_LOCAL_OCR_TEST=1` and a matching test token; it reads only the existing fictional fixtures and is not a hosted test.

Run `npm run build` and `npm test` at the root. Browser E2E is separate (`npm run test:e2e`); some existing browser tests depend on current UI contracts and are not evidence of real hosted processing.

Direct PostgreSQL IPv6 TCP reachability and verify-full TLS authentication for the restricted automatic worker passed on November 14. Automatic-worker startup requires the direct project hostname and unsuffixed dedicated login; there is no automatic pooler fallback. Older administrative and single-job diagnostics may still explicitly use their reviewed session-pooler services. Supabase Auth and owner-scoped PostgREST remain HTTPS. See backend/docs/direct-connection-inventory.md. Never change firewall, add-ons, or database grants without approval.
