# Local development

From the integration repository root, run `npm run dev`. The launcher starts the existing backend on `http://127.0.0.1:3000` and Vite on `http://127.0.0.1:5174`, falling back only to port 5175 if 5174 cannot be bound. Press Ctrl+C to stop its child processes. If port 3000 or both frontend ports are occupied, stop the relevant existing service yourself and retry; the launcher never kills unrelated processes. A different frontend origin may require signing in again.

The backend reads `backend/.env`; Vite reads `frontend/.env`. Keep both private and Git-ignored. The verified local backend settings are `MEDICINE_CATALOGUE_READ_ENABLED=true`, `MEDICINE_CATALOGUE_DEFAULT_SOURCE=official_catalogue`, `PROCESSING_JOB_STORE_ENABLED=true`, and `PROCESSING_WORKER_ENABLED=false`. Existing process environment variables override dotenv; the launcher checks effective values and reports invalid setting names without printing secrets. The `.env.example` defaults are deliberately conservative for unverified environments.

The ordinary command does not launch a processing worker, does not process hosted jobs, and does not configure production. The existing isolated OCR and local persisted-results scripts remain separately guarded; `backend/scripts/run-local-persisted-results.ps1` is a local results server and is not an OCR worker launcher. Run isolated OCR tests only using their existing explicit synthetic fixtures and local database guards; do not point them at hosted queues. Hosted deployment uses separate configuration and requires separate authorization.
